# v0.2.0-rc.1 — GitOps Preview Toolkit

This release candidate renames the project to **gitops-preview-toolkit** and
introduces a plugin-based host for Flux and optional Crossplane desired-state
previews. The canonical repository is
[tobiash/gitops-preview-toolkit](https://github.com/tobiash/gitops-preview-toolkit).
This is a prerelease for evaluation, not a stable promotion.

## What's changed

- `gitops-preview` is the primary command; `fmp` remains a compatibility entry
  point using the same command implementation.
- Persistent local render plugins separate Flux/Git/Helm/path rendering
  (`gitops-preview-flux`) and opt-in Crossplane composition expansion
  (`gitops-preview-crossplane`) from host comparison, policy, AI assessment,
  agent/MCP operations, and reports. The host dependency boundary excludes the
  Helm SDK, Flux libraries, and the Kustomize execution builder.
- Crossplane previews carry stable **Logical Resource Identity** for unnamed
  composed outputs. Composite status and readiness are **Evaluation Evidence**,
  separate from the desired resource inventory. Diff, policy, agent, and report
  consumers retain that distinction.
- Configuration discovery prefers `.gitops-preview.yaml` or
  `.gitops-preview.yml`, with legacy configuration fallbacks.
- Release archives and the Action distribute sibling plugins together. Canonical
  report links, installation paths, and the Action's release download URL use the
  renamed repository. The pre-push Action CLI check builds the complete bundle
  into a temporary directory.
- Reports distinguish unnamed composed resources by their logical identity. The
  overview labels its eight-resource preview and links to the complete list.
- Action manifest exports now write the retained target snapshot, including
  logical outputs, without rerendering or inventing Kubernetes names.

## Installation and packaging

After publication, install the commands at the same explicit RC version:

```sh
go install github.com/tobiash/gitops-preview-toolkit/cmd/gitops-preview@v0.2.0-rc.1
go install github.com/tobiash/gitops-preview-toolkit/cmd/gitops-preview-flux@v0.2.0-rc.1
go install github.com/tobiash/gitops-preview-toolkit/cmd/gitops-preview-crossplane@v0.2.0-rc.1
go install github.com/tobiash/gitops-preview-toolkit/cmd/fmp@v0.2.0-rc.1
```

Alternatively, extract `gitops-preview-toolkit_v0.2.0-rc.1_<os>_<arch>.tar.gz`
into one directory on `PATH`. It contains all four commands. Compatibility
`fmp_v0.2.0-rc.1_<os>_<arch>.tar.gz` archives contain `fmp` and both plugins.
Targets are Linux and macOS, amd64 and arm64. Plugins are resolved beside the
host first, then on `PATH`; installing a host alone is insufficient for rendering.

Pin the Action to `tobiash/gitops-preview-toolkit@v0.2.0-rc.1`; it downloads the
matching toolkit archive. For source/branch testing, build a host and both sibling
plugins and supply the host using the existing `binary` input.

Go's `@latest` prefers stable module versions when available, and GitHub's
`/releases/latest` excludes prereleases. Use the explicit RC tag before promotion.

## Breaking Go API migration

The module path changes from `github.com/tobiash/flux-manifest-preview` to
`github.com/tobiash/gitops-preview-toolkit`. Update all imports, including tests
and architecture/dependency allowlists or forbidden paths. GitHub repository
redirects do not make the old Go module declaration compatible with this release.

`preview.WithHelm` now accepts neutral `*config.HelmSettings`, rather than Helm
SDK CLI settings. For example:

```go
import (
    "github.com/tobiash/gitops-preview-toolkit/pkg/config"
    "github.com/tobiash/gitops-preview-toolkit/pkg/preview"
)

// Supply this option to preview.New; nil uses plugin environment defaults.
opt := preview.WithHelm(&config.HelmSettings{})
```

The SDK-backed path/Kustomize builder has moved to `pkg/build`, constructed with
`build.New(log)`. `pkg/render` is the passive resource collection used by the
host; consumers that execute path builds must use the builder package. Render
execution through the preview host requires the sibling plugin processes.

## Compatibility retained

The `fmp` executable, existing flags and exit codes, `FMP_*` environment variables,
legacy `.fmp.yaml`/`.fmp.yml`/`.github/fmp.yaml` files, producer annotations,
sticky PR comment markers, and report artifact names remain compatible. Archived
sample filenames and payloads retain their historical names. The repository and
Go API migration is separate from these runtime compatibility contracts.

## Requirements and limits

- Crossplane requires explicit trusted invocation opt-in. Repository settings,
  annotations, and agent operation requests cannot grant executable selection
  or development endpoints. Agent/MCP Crossplane use additionally requires
  startup `--trusted`.
- Install the external **Crossplane controller binary v2.4.2**, normally named
  `crossplane-core` on `PATH`, or select it with `--crossplane-engine`. The
  user-facing Crossplane CLI is not this engine. The toolkit checks its version;
  release archives and the Docker Action image do not include it.
- Docker is the default composition function runtime. Trusted per-function
  Development endpoint overrides support explicitly reachable function servers.
  The engine is never downloaded implicitly by the toolkit.
- Rendering is bounded desired-state discovery, not arbitrary cyclic controller
  reconciliation, live-cluster validation, or a prediction of runtime readiness.
  Offline use requires available sources/charts, function images or endpoints,
  and the engine. Local-only agent mode is not an OS sandbox.
- Unsupported inputs and incomplete renders fail rather than presenting an empty
  diff as clean or missing resources as deletions. Completeness covers the
  configured scope, not full Flux feature parity.
- Action SOPS decryption remains unsupported.
